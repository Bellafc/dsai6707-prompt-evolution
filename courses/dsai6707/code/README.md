# evo_prompt: multi-objective evolution of a prompt set for three economic-school LLM agents

Code for the DSAI6707 project report. It searches prompt sets for the Keynesian, Austrian and Monetarist agents with
NSGA-II, a GA, random search and an NSGA-II ablation, and re-measures the chosen prompt sets on held-out synthetic
events. Everything the report reports is regenerated from the committed raw outputs in `../results/`.

The package imports the thesis harness `mosaic` (read-only). It does not modify `src/mosaic`, `configs/` or `tests/`.

## 1. Environment

- Python 3.10 or newer (tested with Python 3.13).
- Dependencies:
  - `mosaic` from the repository root: `pip install -e .` (needs `numpy`).
  - `matplotlib` (figures), `pytest` (tests), `openai` (only if you use the official client; the runner uses the standard library).
- No GPU, no vLLM, no network are needed to run the tests, the analysis or the figures.

```bash
# from the repository root
python -m pip install -e .
python -m pip install matplotlib pytest
```

## 2. Data preparation

No data files are needed. Events are synthetic and generated by `mosaic.teacher.make_items`:

- search set: `make_items(5, seed=23)`, keynesian items (5 events);
- held-out set: `make_items(10, seed=29)`, keynesian items (10 events).

Seeds 11 (thesis disagreement matrix) and the thesis held-out files are never used. The protocol is in `PROTOCOL.md`.

## 3. Running the search

The runner is `evo_prompt.runner`. Run it from `courses/dsai6707/code`.

```bash
cd courses/dsai6707/code

# offline check (deterministic fake model, no network, a few seconds)
python -m evo_prompt.runner --offline --methods nsga2 ga random b0 --seeds 1 --gens 2 --pop 4 --heldout \
  --cache /tmp/offline_cache.jsonl --out /tmp/offline_runs

# full matrix, as run for the report (needs an OpenAI-compatible endpoint; see section 4)
python -m evo_prompt.runner --methods b0 nsga2 ga random nsga2_rule --seeds 1 2 3 \
  --gens 4 --pop 6 --heldout --budget 30 --out ../results/runs
# ablation arms of PROTOCOL_ADDENDUM_A.md (same settings)
python -m evo_prompt.runner --methods ga_rule nsga2_llmu --seeds 1 2 3 --gens 4 --pop 6 --heldout --budget 15

# second-model replication on Claude Haiku 5.5 (PROTOCOL_ADDENDUM_B.md to _D.md); needs ANTHROPIC_API_KEY in the
# environment and `pip install anthropic`; everything goes to ../results/haiku/
python -m evo_prompt.runner --profile haiku --methods b0 nsga2 ga random nsga2_rule ga_rule nsga2_llmu \
  evoprompt_ga evoprompt_ga_lc --seeds 1 2 3 4 5 --gens 4 --pop 6 --heldout --budget 15
# the report's runs were split into parallel processes with --cache-base (frozen shared cache) and one --cache layer
# per arm or seed; the exact split is described in PROTOCOL_ADDENDUM_C.md

# tables and figures (cache only, no model calls)
python -m evo_prompt.analyze && python -m evo_prompt.figures
python -m evo_prompt.analyze --profile haiku && python -m evo_prompt.figures --profile haiku
```

Methods:

| `--methods` | What it is |
|---|---|
| `b0` | Hand-written prompt set (`mosaic.divergence.profiles`), three sampling seeds |
| `nsga2` | NSGA-II with structural crossover, rule mutation and LLM-guided mutation (the proposed method) |
| `ga` | Single-objective GA (feasibility first, then equal-weight sum), same operators as `nsga2` |
| `random` | B1 random search: independent rule perturbations of B0, same number of evaluations |
| `nsga2_rule` | Ablation: NSGA-II without LLM-guided mutation |
| `ga_rule` | Ablation: the GA with rule mutation only (completes the 2 x 2 design; addendum A) |
| `nsga2_llmu` | Control: NSGA-II with an LLM mutation that carries no objective information (addendum A) |
| `evoprompt_ga` | Published baseline: EvoPrompt (GA), Guo et al. ICLR 2024, adapted to prompt sets (addendum C) |
| `evoprompt_ga_lc` | The same with one length sentence added to the template (addendum D, post hoc) |

Each search run writes to `../results/runs/<method>_s<seed>/`:

- `gen_log.csv`: per generation, hypervolume, archive size, best fidelity and disagreement, API calls and spend so far;
- `evaluations.jsonl`: every evaluated prompt set with its origin (`init`, `x`/`c` crossover or copy, `R` rule mutation, `L` LLM mutation, `f` LLM output rejected and replaced by rule mutation);
- `front.jsonl`: the final feasible non-dominated archive;
- `final.json`: summary, knee solution on the search events, and the held-out re-measurement.

The knee solution is also written to `../results/best_prompts/<method>_s<seed>_knee.txt`.

### Resuming and budget

Every model call is stored in `../results/cache/llm_cache.jsonl`, keyed by the model, the messages and the sampling
parameters. The search is deterministic given its seed, so an interrupted run is resumed by running the same command again:
finished calls are read from the cache and the trajectory is replayed. A USD budget ledger stops the run cleanly when the
estimated spend reaches `--budget`.

## 4. Model endpoint and secrets

The runner calls an OpenAI-compatible chat endpoint. Defaults are in `evo_prompt/config.py`:

- model `qwen3.8-max`, base URL `https://token-plan.maas.qianwenaiapi.com/compatible-mode/v1`;
- temperature 0.7, top-p 0.9, max 1,024 output tokens, thinking disabled.

The API key is never written to the repository. If `OPENAI_API_KEY` is set in the environment it is sent as a bearer
token; otherwise the calls go without an explicit header, which works where a proxy adds the credential for the host.
Override the endpoint with `--base-url` and `--model`.

The USD spend is an **estimate**: `PRICE_IN_PER_MTOK = 2.4` and `PRICE_OUT_PER_MTOK = 9.6` in `config.py` are assumed list
prices. The measured token counts are stored in the cache, so the cost can be recomputed with the provider's price sheet.

## 5. Analysis and figures (no model calls)

```bash
cd courses/dsai6707/code
python -m evo_prompt.analyze      # tables and paired tests; reads the cache only
python -m evo_prompt.figures      # hypervolume curves, Pareto fronts, held-out bars
```

`analyze` re-scores the held-out events per event from the cache. A missing cache entry raises an error rather than calling the API.

Outputs in `../results/`:

| File | Content |
|---|---|
| `summary_table.md` | search-level and held-out tables, paired tests (mean ± sd over seeds) |
| `summary.csv` | one row per run (search and held-out metrics) |
| `summary_search.csv` | one row per search run |
| `heldout_per_event.csv` | per held-out event, averaged over seeds |
| `heldout_tests.csv` | paired differences from B0, 95% bootstrap CI (`mosaic.stats.paired`), exact sign-flip p-values over the 10 events, Holm-adjusted p-values |
| `heldout_tests_protocol.csv` | the full test family of `PROTOCOL.md`: every method-vs-B0 and method-vs-method test, Holm over the whole family |
| `addendum_a_search.csv` | per-seed final-hypervolume differences for Q1 to Q5 with the exact one-sided sign-flip p-value |
| `figures/*.png` | `hv_vs_generation.png`, `pareto_fronts.png`, `heldout_bars.png` |

## 6. Tests

```bash
# from the repository root; must pass before each commit that touches courses/dsai6707/code
python -m pytest -q courses/dsai6707/code
# the repository's own suite must still pass
python -m pytest -q
```

The 20 course tests run offline with the deterministic `OfflineBackend`. They cover the hypervolume and dominance
machinery, the genome decoding, the operators, the evaluator's caching and feasibility, and the search drivers.

## 7. Layout

```
code/
  README.md            this file
  PROTOCOL.md          analysis protocol (committed during the main matrix run; see report section 4.8)
  PROTOCOL_ADDENDUM_A.md .. _D.md   addenda, each committed before the runs it governs (D is post hoc)
  conftest.py          puts evo_prompt on the import path for pytest
  evo_prompt/
    config.py          protocol constants (seeds, events, feasibility, reference point, model, budget)
    genome.py          representation: school genes, prompt sets, decoding through mosaic.divergence.messages
    evaluate.py        objectives: fidelity, disagreement, validity, length; the evaluator with memoisation
    operators.py       rule mutation, structural crossover, LLM-guided mutation (plan, prompt, validated apply)
    moo.py             constrained dominance, fast non-dominated sort, crowding, exact 3-D hypervolume, knee
    algorithms.py      Search class: NSGA-II, GA, random, the ablations, EvoPrompt (GA); archive and history
    backend.py         concurrent OpenAI-compatible backend, Anthropic SDK backend (Haiku), layered cache, USD ledger,
                       and OfflineBackend (deterministic fake model for tests and dry runs)
    runner.py          command line: search runs, B0, held-out re-measurement
    analyze.py         tables and exact paired tests (cache only)
    figures.py         report figures
  tests/
    test_moo.py
    test_genome_operators.py
    test_search_offline.py
```

## 8. Reproduction checklist

1. `pip install -e .` at the repository root and `pip install matplotlib pytest`.
2. `python -m pytest -q courses/dsai6707/code` passes offline.
3. `python -m evo_prompt.analyze` and `python -m evo_prompt.figures` reproduce the tables and figures from `../results/` with no API access.
4. To re-run the search from scratch, delete `../results/cache/llm_cache.jsonl` (this changes the outputs, since the model is not deterministic across providers) and run the command in section 3.
